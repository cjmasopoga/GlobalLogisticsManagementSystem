    .ToListAsync();
MVC app knew about EF, database schema, SQL Server
✅ After (Thin Client) 
// Controller calls the API
var clients = await _api
    .GetClientsAsync();
MVC app only knows about DTOs and HTTP

ApiService is a typed HttpClient wrapper that:
  • Attaches the JWT token from session to every request
  • Serialises/deserialises JSON with System.Text.Json
  • Provides a strongly-typed async method for every API endpoint

🔐 Authentication & Security

JWT Token Flow

  1. User submits login form (username + password)
  2. MVC POSTs to POST /api/auth/login
  3. API validates credentials → returns JWT
  4. MVC stores token in server-side session
  5. Every API call attaches Authorization: Bearer <token>
  6. SessionAuthFilter redirects to login if no token found
Logout clears the entire session — token is immediately invalidated on the client side

Token Settings

SessionAuthFilter — global IActionFilter
Checks for JwtToken in session on every request.
Passes the Account controller (Login/Logout) through without a token.

🔬 Integration Test Design

Key Engineering Decisions

1. Shared InMemoryDatabaseRoot
A single static readonly InMemoryDatabaseRoot is passed to UseInMemoryDatabase. Without this, each HTTP request scope got a brand-new empty database — data written in one request was invisible in the next.
2. Service Descriptor Removal
All EF Core descriptors involving ApiDbContext are removed from the DI container before registering InMemory, preventing the "SqlServer + InMemory providers both registered" runtime error.
3. EnableServiceProviderCaching(false)
Prevents EF from reusing a cached internal service provider that still holds SQL Server internals.
4. Testing Environment Guard
ASPNETCORE_ENVIRONMENT=Testing causes the API to skip db.Database.Migrate() on startup — migrations would fail against an InMemory store.
